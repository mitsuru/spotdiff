# spotdiff 初期設計

## 目的と合意済みの方針

Rustで、Kitty Graphics Protocolを使って画像の変更前後を確認するターミナルツールを作る。
主な用途は、lazygitで選択した画像をキー操作で全画面ビューアに開き、終了するとlazygitに戻ること。
単体でも2つの画像ファイルを比較できるようにする。

全画面ビューアを主機能とし、画像diff生成とターミナル描画を分離する方針はユーザーと合意済み。
以下のCLI、操作、対応形式、境界条件は、その方針を具体化した初期仕様案として確認する。

## 採用する構成と代替案

- 採用：独立した全画面TUIをlazygitのカスタムコマンドから起動する。Rust側で画面と入力を管理できる。
- 将来の拡張：lazygitのdiffパネル内に表示する。画像の配置、リサイズ、ポップアップ時の非表示など、lazygit側との協調が必要になる。
- 別案：Kittyの別ウィンドウに表示する。元のターミナル画面から離れるため、初期版には採用しない。

初期版でパネル内表示を約束せず、diff生成処理を再利用できる構造までを用意する。常駐プロセスやIPCは追加しない。

## 初期版の範囲

- 静止画像のPNG、JPEG、WebPを読み込む。
- 変更前後の左右比較と、変更箇所を強調する表示を切り替える。
- 透過部分を市松模様で表示する。
- 画面へのフィット、ズーム、表示位置の移動に対応する。
- Gitの未ステージ変更、ステージ済み変更、新規追加、削除を扱う。
- lazygitのFilesパネル用の設定例を提供する。
- Kittyを直接使う環境を最初の実機検証対象とする。

アニメーション、SVGのラスタライズ、知覚的な類似度判定、画像の編集、ステージ操作、コミット間比較、リネーム追跡、tmux経由の動作保証は初期版の範囲外。

## CLIとGitの比較対象

```text
spotdiff before.png after.png
spotdiff git -- path/to/image.png
spotdiff git --staged -- path/to/image.png
```

| 呼び出し | 変更前 | 変更後 |
| --- | --- | --- |
| 2ファイル指定 | 第1引数のファイル | 第2引数のファイル |
| `git` | index | 作業ツリー |
| `git --staged` | HEAD | index |

Gitモードのパスは呼び出し時の作業ディレクトリから解決し、リポジトリ内のパスに変換する。
Git CLIを子プロセスとして使用し、引数を個別に渡す。画像内容はバイト列で取得し、シェルの文字列展開を使わない。
Gitの比較元を取得する際に、作業ツリーやindexを書き換えない。

片側だけに画像がある追加・削除では、存在しない側に「追加前の画像なし」または「削除後の画像なし」と表示する。
未追跡の画像は新規追加として表示する。初回コミット前の`--staged`ではHEAD側を画像なしとして扱う。
両側にファイルが存在しない場合はエラーにする。
通常の2ファイル指定では、指定ファイルがない場合は入力エラーとし、追加・削除として扱わない。
Gitコマンドの失敗と、比較対象にファイルが存在しないことを区別する。権限エラーや破損したリポジトリを画像なしとして扱わない。
リネームでは指定されたパスの追加・削除として扱い、変更前の別パスを自動推測しない。
Git LFSポインタの解決は行わず、画像として読み込めないことを明示する。

## 表示と操作

上部に対象名、比較元、画像サイズを表示する。中央に画像、下部に表示モード、倍率、変更ピクセル数、操作案内を表示する。
初期表示は左右比較と画面フィット。左右で同じ画像座標、倍率、表示位置を使用して位置の比較を可能にする。

| キー | 操作 |
| --- | --- |
| `Tab` | 左右比較と差分強調を切り替える |
| `+` / `-` | ズームイン / ズームアウト |
| 矢印キー / `h j k l` | 共通の表示位置を移動する |
| `f` | 画面フィットに戻す |
| `1` | 画像の1ピクセルを端末の1ピクセルに合わせる |
| `q` / `Esc` / `Ctrl-C` | 終了する |

倍率は1/16倍から16倍までとし、フィット倍率は別途計算する。画像外へ際限なく移動できないよう表示位置を制限する。
リサイズ時は表示領域を再計算する。フィット中は倍率も更新し、手動ズーム中は倍率を維持して表示位置を制限し直す。
表示領域が小さすぎる場合は画像を配置せず、ウィンドウを広げる案内と終了操作を表示する。
マウス操作は初期版では追加しない。

## 差分の定義

画像を8ビットRGBAにデコードした後、拡大縮小する前のピクセルで比較する。
比較キャンバスは両画像の幅・高さそれぞれの最大値とし、両画像を左上に揃える。サイズ変更を自動で正規化しない。

両方にピクセルがある位置では、RGBAのいずれかの値が異なれば変更として扱う。
ただし、両方とも完全に透明なピクセルではRGB値の違いを無視する。
片側にだけピクセルが存在する位置は変更とする。両側とも範囲外の位置は比較対象から除外する。
変更率の分母は、少なくとも片側にピクセルが存在する位置の総数とする。

差分強調表示は変更後の画像を基準とし、変更箇所にマゼンタを半透明で重ねる。
変更後に存在しない削除領域は変更前の画像を基準に強調する。強調箇所は透明なピクセル上でも見えるよう市松模様の上に合成する。
変更のない箇所は暗くして、変更位置を見つけやすくする。
ピクセル比較と統計は描画方式に依存させず、表示用の縮小画像を比較に使用しない。

## コンポーネントとデータの流れ

単一のCargoパッケージに、小さなモジュールを用意する。

1. `cli`：引数を解釈して、2ファイル比較またはGit比較の要求を作る。
2. `source`：ファイルまたはGitから両側のバイト列と表示用メタデータを取得する。
3. `diff`：画像をデコードし、差分マスクと統計、表示用画像を生成する。端末、キー入力、Gitには依存しない。
4. `app`：表示モード、倍率、表示位置を管理し、入力から状態を更新する。
5. `render`：状態と画像をKitty Graphics Protocolで描画する。
6. `terminal`：端末への出入り、raw mode、カーソル、画像の後片付けを管理する。

`入力 → source → diff → app/render → 端末`の順でデータを渡す。
将来のパネル内表示では、`source`と`diff`を使い、全画面TUIとは別の描画経路を追加できる。
初期版で汎用的な描画プラグインの仕組みや公開APIを設ける必要はない。

依存ライブラリの候補は`clap`、`image`、`ratatui`、`crossterm`、`ratatui-image`。
依存バージョンとfeatureは実装計画時に公式情報と互換性を確認して決める。
Kitty方式を選択し、非対応環境で文字による画像表示へ自動で切り替えない。
`ratatui-image`の不要な描画バックエンドやChafaの依存は有効にしない。
端末問い合わせを利用して対応と文字セルのピクセルサイズを確認し、問い合わせが応答しない場合は有限時間で失敗させる。

画像の解析と差分生成を済ませてからTUIを開始する。描画のためのリサイズとエンコードは変更時に行い、キー操作ごとに元画像のデコードやdiff計算を繰り返さない。
表示更新で画像処理が必要な場合はワーカースレッドへ渡し、古い状態の結果で最新の表示を上書きしない。

## lazygitとの連携

Filesパネルのカスタムコマンドで、選択したファイル名を`quote`して渡し、`output: terminal`で全画面ビューアを起動する。
未ステージ変更があれば`spotdiff git`、未ステージ変更がなくステージ済み変更だけがあれば`spotdiff git --staged`を選ぶ。
両方に変更がある場合は未ステージを優先し、ステージ済み比較を明示的に開く別コマンドも提供する。
キーの初期案は`I`とし、ステージ済み比較は`<c-s>`とする。既存キーとの重複がある場合は設定例で変更可能と説明する。
設定例はリポジトリに置き、ユーザーのlazygit設定ファイルへの書き込みは行わない。
画像以外を選んだ場合もツール側で入力形式を検査し、説明付きのエラーを返す。

## エラー処理と端末の復元

TTY以外の入出力、Kitty非対応、未対応形式、デコード失敗、Git取得失敗では原因を示して非ゼロで終了する。
画像が等しい場合もビューアを開き、変更ピクセル数0として表示する。正常なビューア終了の終了コードは差分の有無によらず0とする。
巨大な画像の読み込みではデコーダの制限を利用する。初期版では各入力のデコード後のRGBAサイズと比較キャンバスサイズをそれぞれ256 MiB以下に制限し、オーバーフローする寸法は拒否する。

通常終了、`Ctrl-C`、途中のエラー、panicで、raw mode、代替画面、カーソル表示を復元する。
描画に使用した画像だけを削除し、端末内の他の画像を一括削除しない。
端末の復元後にエラーを表示し、lazygitへ戻ったときに画像や入力モードが残らないようにする。

## 検証と完成条件

- ピクセル差分：同一画像、RGB変更、alpha変更、完全透明RGBの違い、異なる寸法、片側なしを検証する。
- Git入力：一時リポジトリでindex/作業ツリーとHEAD/indexが異なる画像を取得すること、新規・削除、未追跡、初回コミット前、サブディレクトリ、空白を含むパスを検証する。
- 表示状態：左右で倍率と位置を共有し、リサイズと移動限界が正しいことを検証する。
- Rustの標準チェック：`cargo fmt --check`、`cargo test`、`cargo clippy --all-targets -- -D warnings`を実行する。
- Kitty実機：左右比較、差分強調、透過表示、1倍表示、ズーム、移動、リサイズ、通常終了、`Ctrl-C`を確認する。
- lazygit実機：未ステージとステージ済みの呼び出し、画像以外のエラー、終了後の画面復帰を確認する。

自動テストだけでKitty描画やlazygitへの復帰が検証済みとは扱わない。
実機が利用できない場合は、未確認の操作と手動検証手順を明記する。
