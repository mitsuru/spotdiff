# 実機検証

## 自動検証の範囲

Rustテストは実Gitの入力、RGBA差分、表示状態、Kitty制御列、CLIエラーを確認する。PythonのPTYテストは端末応答を模擬して起動・終了とtermios、カーソル、代替画面の復元を確認する。

PTYは画面に画像を描画する端末エミュレータではないため、以下は実機で確認する。

## Kittyでの表示

1. Kittyを直接起動する。tmux/screenを通さず、`spotdiff`をPATHに置く。
2. 内容の異なるPNG・JPEG・WebPをそれぞれ2枚用意する。`spotdiff before.png after.png`を実行する。
3. 左右に画像が出て、縦横比が正しく、変更前後の位置が揃うことを確認する。
4. `Tab`で差分強調へ切り替え、変更部分がマゼンタで見えることを確認する。
5. `+ -`でズーム、矢印またはhjklで移動する。左右の倍率と位置が揃い、画像の端で移動が止まることを確認する。
6. `1`で1倍、`f`でフィットする。透明なPNGでは市松模様が表示され、完全透明部分の変更も強調できることを確認する。
7. ウィンドウを連続でリサイズする。fit中の倍率更新と手動ズームの倍率維持、小画面からの復帰を確認する。
8. 表示切り替えとズームを連続で行ってから終了し、古い画像が残らないことを確認する。
9. `q`、`Esc`、`Ctrl-C`でそれぞれ終了する。元の画面・カーソル・キー入力が復元され、通常のコマンドを実行できることを確認する。
10. 同じ画像、サイズ違い、透明PNGのalpha違いも比較し、変更数と強調位置を確認する。

## lazygitへの復帰

使い捨てのGitリポジトリで行う。

1. 画像をcommitする。その画像を編集してlazygitを開き、設定例を追加する。
2. Filesパネルで画像を選択して`I`を押す。indexと作業ツリーが表示されることを確認する。
3. `q`で終了して復帰プロンプトでEnterを押し、lazygitの選択・キー操作・表示が復元され、画像が残らないことを確認する。
4. 画像をstageして`I`と`Ctrl-S`を試す。HEADとindexの比較になることを確認する。
5. stageした後にさらに編集し、`I`で未ステージ、`Ctrl-S`でステージ済みが開くことを確認する。
6. 新規画像、未追跡画像、`git add -N`した画像、削除画像、初回commit前のstage済み画像も開き、画像なし側の説明を確認する。
7. 空白・引用符を含む画像名でも起動できることを確認する。
8. テキストファイルや破損画像でエラーを出し、lazygitへ戻れることを確認する。
9. 表示中に端末サイズを変えて終了し、lazygitのレイアウトが復元されることを確認する。

## 実施記録

2026-09-28、Linux、Rust 1.96.0、lazygit 0.65.0で以下を実施した。

- Rustテスト39件、fmt、Clippy（全target、警告をエラー扱い）、releaseビルドが通過。
- PTYテスト5件が通過。応答なしの失敗、q/Esc/Ctrl-C、エラー/panic、個別のズーム・移動・モード切替、2回の端末サイズ変更、FIFOの拒否を確認。画像送信の完了を待ちながら操作し、termios・カーソル・代替画面が復元された。
- 一時リポジトリと一時設定を使い、実際のlazygitからの起動・復帰をPTYで確認。未ステージ、ステージ済み、両方ある場合のI、両方ある場合のCtrl-Sの4通りが通過。空白・引用符・日本語を含むファイル名でも比較元が正しく、画像送信後にq→Enterでlazygitへ戻り、さらにqで終了してtermiosが復元された。

これらのPTYではKittyの問い合わせ応答を模擬している。Kittyの実画面は操作・観察できないため、画像の見え方、透過表示、古い画像の残留、lazygitの実画面での表示と選択の復元は未確認。実機確認後は端末バージョンと確認項目をここに追記する。
